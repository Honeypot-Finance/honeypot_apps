This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

This is a DeFi/Web3 monorepo containing multiple Next.js applications managed by Nx. The project consists of trading platforms, vaults, launchpads, and DEX interfaces built with TypeScript, React, and Web3 technologies.

## Essential Commands

### Development
```bash
# Run specific apps (shortcuts available)
pnpm p              # pot2pump on port 9001
pnpm w              # wasabee on port 9002
pnpm bgt-market     # bgt-market on port 9003
pnpm dreampad       # dreampad on port 9004
pnpm all-in-one-vault # all-in-one-vault on port 9006

# Or use Nx directly
npx nx dev <app-name>
```

### Build & Deploy
```bash
# Build for production
npx nx build <app-name> --prod

# Build wasabee shortcut
pnpm wb
```

### Code Generation
```bash
# Generate GraphQL types (run from app directory)
cd apps/<app-name>
npx graphql-codegen --config algebra_codegen.ts

# Generate Wagmi contract types
sudo pnpm wagmi generate --root apps/<app-name>
```

### Testing & Linting
```bash
# Lint specific app
nx lint <app-name>

# Test library
nx test <lib-name>
```

### Create New Components
```bash
# Create new app (without app router)
npx nx g @nx/next:app apps/<app-name>
# Select: no unit tests, no E2E tests, no App Router, no src directory

# Create new library
npx nx generate @nrwl/react:lib libs/<lib-name>
```

## Architecture & Key Patterns

### 1. App Structure Pattern
Each app follows this structure:
```
apps/[app-name]/
├── pages/          # Next.js pages (Pages Router, not App Router)
├── components/     # React components (atoms → molecules → organisms)
├── services/       # MobX stores for state management
├── lib/           # Utilities, hooks, ABIs
└── config/        # App-specific configuration
```

### 2. State Management
Uses MobX with service pattern:
```typescript
class ServiceName {
  constructor() {
    makeAutoObservable(this);
  }
}
export const serviceName = new ServiceName();
```

### 3. Provider Hierarchy
Consistent provider wrapping in `_app.tsx`:
- WagmiProvider → QueryClientProvider → ApolloProvider → tRPC → RainbowKit → NextUI → Custom providers

### 4. Import Conventions
- `@/` - App-specific imports
- `@honeypot/shared` - Shared SDK imports (requires tsconfig.json path mapping)

### 5. API Patterns
- **tRPC**: Internal type-safe APIs
- **GraphQL**: Blockchain data from subgraphs
- **Wagmi hooks**: Contract interactions
- **REST**: External service integration

### 6. Contract Integration
All contract interactions wrapped in service classes with type-safe interfaces generated by Wagmi CLI.

## Tech Stack Reference

- **Framework**: Next.js 14 (Pages Router)
- **Web3**: Wagmi v2, Viem v2, RainbowKit, ethers.js v6
- **State**: MobX (services pattern), Zustand, Recoil
- **UI**: NextUI, Tailwind CSS, Radix UI, Framer Motion
- **Data**: tRPC, Apollo GraphQL, TanStack Query
- **DeFi SDKs**: @cryptoalgebra/sdk, custom honeypot-sdk
- **Monitoring**: Sentry, Vercel Analytics

## Important Notes

1. **No App Router**: All apps use Next.js Pages Router
2. **Library Imports**: Manual path configuration needed in each app's tsconfig.json
3. **Port Allocation**: Each app has a dedicated port (9001-9006)
4. **Wallet Integration**: Multiple wallet support via RainbowKit + custom providers
5. **Multi-chain**: Configured for multiple EVM chains
6. **Error Boundaries**: Wrap major sections for better error handling
