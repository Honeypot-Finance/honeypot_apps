## Repository Overview

This is a DeFi/Web3 monorepo containing multiple Next.js applications managed by Nx. The project consists of trading platforms, vaults, launchpads, and DEX interfaces built with TypeScript, React, and Web3 technologies.

## Essential Commands

### Development
```bash
# Run specific apps (shortcuts available)
pnpm p              # pot2pump on port 9001
pnpm w              # wasabee on port 9002
pnpm bgt-market     # bgt-market on port 9003
pnpm dreampad       # dreampad on port 9004
pnpm all-in-one-vault # all-in-one-vault on port 9006

# Or use Nx directly
npx nx dev <app-name>
```

### Build & Deploy
```bash
# Build for production
npx nx build <app-name> --prod

# Build wasabee shortcut
pnpm wb

# TypeScript type checking (no build output)
npx tsc --noEmit -p apps/<app-name>/tsconfig.json
```

### Code Generation
```bash
# Generate GraphQL types (run from app directory)
cd apps/<app-name>
npx graphql-codegen --config algebra_codegen.ts

# Generate Wagmi contract types
sudo pnpm wagmi generate --root apps/<app-name>
```

### Testing & Linting
```bash
# Lint specific app
npx nx lint <app-name>

# Lint with auto-fix
npx nx lint <app-name> --fix

# Test library
npx nx test <lib-name>

# Show all available targets for a project
npx nx show project apps/<app-name>
```

### Create New Components
```bash
# Create new app (without app router)
npx nx g @nx/next:app apps/<app-name>
# Select: no unit tests, no E2E tests, no App Router, no src directory

npx nx generate @nrwl/react:lib libs/<lib-name>
```

## Architecture & Key Patterns

### 1. App Structure Pattern
Each app follows this structure:
```
apps/[app-name]/
├── pages/          # Next.js pages (Pages Router, not App Router)
├── components/     # React components (atoms → molecules → organisms)
│   ├── algebra/    # DEX/AMM specific components
│   └── cross-chain-swap/ # Cross-chain swap components
├── services/       # MobX stores for state management
├── lib/           # Utilities, hooks, ABIs
│   └── algebra/   # Algebra DEX specific logic
└── config/        # App-specific configuration
```

### 2. State Management
Uses MobX with service pattern:
```typescript
class ServiceName {
  constructor() {
    makeAutoObservable(this);
  }
}
export const serviceName = new ServiceName();
```

Key services:
- `wallet` - Wallet connection and chain management
- `crossChainSwapService` - Cross-chain swap logic
- `crossChainTransactionService` - Transaction history
- `universalAccountService` - Particle Network Universal Account

### 3. Provider Hierarchy
Consistent provider wrapping in `_app.tsx`:
- WagmiProvider → QueryClientProvider → ApolloProvider → tRPC → RainbowKit → NextUI → Custom providers

### 4. Import Conventions
- `@/` - App-specific imports
- `@honeypot/shared` - Shared SDK imports (requires tsconfig.json path mapping)
- `@cryptoalgebra/sdk` - Algebra DEX SDK

### 5. API Patterns
- **tRPC**: Internal type-safe APIs (price feeds, data aggregation)
- **GraphQL**: Blockchain data from subgraphs
- **Wagmi hooks**: Contract interactions
- **REST**: External service integration (Defined.fi, CoinGecko)

### 6. Contract Integration
All contract interactions wrapped in service classes with type-safe interfaces generated by Wagmi CLI.

### 7. Token Handling
- Native tokens use `0x0000000000000000000000000000000000000000` address
- Wrapped tokens provide logoURI fallback for native tokens
- Token metadata cached in MobX stores
- Balance updates via polling and block watching

### 8. Cross-Chain Architecture
- **Universal Account** (Particle Network): Handles cross-chain operations
- **Flow**: Deposit → Convert → Withdraw
- **Price Feeds**: Multiple providers (Defined.fi, local oracles)
- **Transaction States**: pending → completed/failed
- **Balance Caching**: 30-second cache with manual refresh

## Tech Stack Reference

- **Framework**: Next.js 14 (Pages Router)
- **Web3**: Wagmi v2, Viem v2, RainbowKit, ethers.js v6
- **State**: MobX (services pattern), Zustand, Recoil
- **UI**: NextUI, Tailwind CSS, Radix UI, Framer Motion
- **Data**: tRPC, Apollo GraphQL, TanStack Query
- **DeFi SDKs**: @cryptoalgebra/sdk, custom honeypot-sdk, Particle Network SDK
- **Monitoring**: Sentry, Vercel Analytics

## Important Notes

1. **No App Router**: All apps use Next.js Pages Router
2. **Library Imports**: Manual path configuration needed in each app's tsconfig.json
3. **Port Allocation**: Each app has a dedicated port (9001-9006)
4. **Wallet Integration**: Multiple wallet support via RainbowKit + Particle Network
5. **Multi-chain**: Configured for multiple EVM chains (Ethereum, BSC, Base, Berachain, etc.)
6. **Error Boundaries**: Wrap major sections for better error handling
7. **Lazy Loading**: Some libraries marked as lazy-loaded to reduce bundle size
8. **Contract Addresses**: Stored in `config/contractAddresses.ts` per app

## Common Issues & Solutions

1. **Permission errors with Nx**: Remove `.nx` directory and retry
2. **Missing token logos**: Native tokens use wrapped token logos as fallback
3. **Balance not updating**: Clear cache with `clearBalanceCache()` method
4. **Cross-chain swap stuck**: Check Universal Account balance and network status
5. **TypeScript errors**: Run `npx tsc --noEmit` to check without building
